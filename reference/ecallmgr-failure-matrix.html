ecallmgr alone (FS + AMQP + DB)

  • Registration table. ETS (ecallmgr_registrar.erl:382), used for device bridges (ecallmgr_util.erl:1182 → ecallmgr_registrar.erl:189), misses go to peer ecallmgrs only (:561), serves reg_query (:46–60). Not refilled from FS on boot.
  • SIP auth cache. ecallmgr_fs_authn.erl:295.
  • acl.conf / sofia.conf. ecallmgr_fs_config.erl:162–183.
  • Channel tracking and queries. ecallmgr_fs_channels.erl:56–68; re-sync on connect, ecallmgr_fs_node.erl:288.
  • FS connection management.

ecallmgr needs a kapp for

  • Routing (ecallmgr_fs_router_util.erl:44), authz/rating via jonny5 and hotornot (ecallmgr_fs_authz.erl:158, 291), the balance crawler via jonny5 (ecallmgr_balance_crawler_worker.erl:32), auth cache misses via registrar (ecallmgr_fs_authn.erl:323), media URLs via media_mgr (ecallmgr_util.erl:1479), conference config (ecallmgr_fs_config.erl:456), and every in-call command.

OTP facts

  • Kapps are started with application:ensure_all_started/1, which makes them temporary (core/kazoo_apps/src/kapps_controller.erl:98; docs). A kapp dying doesn't stop the node.
  • kapps_controller:restart_app/1 restarts one kapp in place (:139).
  • Memory, atoms, processes and ETS are shared per node (system limits).

Glossary

Node
One BEAM VM, which is one OS process, e.g. ecallmgr@host.
Kapp
A Kazoo OTP application started by kapps_controller (callflow, registrar, jonny5, …).
Combined node
A node running ecallmgr plus the other kapps, which is what PR #76's default produces.
Registration table
ecallmgr's ETS table of contacts: the only record of where each phone can be reached.
Blast radius
Everything that stops when one thing fails or restarts.
VM-wide fault
A failure of shared VM resources that OTP supervision can't contain.
